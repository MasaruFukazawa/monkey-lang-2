# monkey-lang-2

Go で書く、プログラミング言語 Monkey のインタプリタです。

## 必要なもの

- Docker（Docker Compose v2 を含む）
- make

Go は手元に入れなくて構いません。Go 1.27 はコンテナの中で動きます。

## 始め方

次の 2 つのコマンドで、コンテナを起動してテストを実行できます。

```sh
make up    # イメージを作ってコンテナを起動する
make test  # コンテナの中で go test ./... を実行する
```

作業を終えるときは、次のコマンドでコンテナを止めます。

```sh
make down
```

## make コマンドの一覧

すべてのコマンドは、`make up` で起動したコンテナの中で実行されます（`up` と `down` を除く）。

| コマンド | このコマンドがすること |
|---|---|
| `make up` | イメージを作ってコンテナを起動する |
| `make down` | コンテナを止めて消す |
| `make shell` | コンテナの中のシェルに入る |
| `make run` | `go run .` でプログラムを実行する |
| `make test` | `go test ./...` ですべてのテストを実行する |
| `make fmt` | `go fmt ./...` でコードを整形する |
| `make vet` | `go vet ./...` でコードの怪しい箇所を調べる |
| `make tidy` | `go mod tidy` で依存ライブラリの一覧を整える |

## 開発環境の仕組み

- **手元のフォルダとコンテナの `/app` は同じ中身です。** 手元でファイルを編集すると、コンテナの中にもすぐに反映されます。
- **ダウンロードしたライブラリとビルド結果は、Docker の volume（Docker が管理する保存場所）に残ります。** コンテナを作り直しても、再ダウンロードと再ビルドをせずに済みます。
- **cgo（Go から C 言語のコードを呼ぶ機能）は無効にしています。** 土台にしている `golang:1.27-alpine` イメージには C コンパイラが入っていないためです。

## ファイル構成

| パス | このファイルの役割 |
|---|---|
| `Dockerfile` | 開発用コンテナのイメージを定義する |
| `compose.yaml` | コンテナの起動方法（フォルダの共有・volume）を定義する |
| `Makefile` | よく使う操作を `make` コマンドにまとめる |
| `go.mod` | Go のモジュール名と Go のバージョンを定義する |
| `src/` | ソースコードを置くディレクトリ |
